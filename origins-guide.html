Welcome to Origins Builder

Origins Builder is a visual tool for creating custom Origins for the Minecraft Origins mod (Forge 1.20.1). Instead of writing JSON by hand, you build powers visually using a block-based editor — then export a ready-to-use datapack.

This guide explains how the Origins mod works and how to use Origins Builder to go from an idea to a working datapack.

💡 Tip

If you already know how Origins works, skip straight to Using the Editor or Using the Manager.

Origins Mod

What is Origins?

Origins is a Minecraft mod that lets players choose a species or origin at the start of a world, each with unique abilities, strengths, and weaknesses.

Origins are defined through datapacks — JSON files that tell the mod what powers each origin has, what those powers do, and under what conditions they activate. Origins Builder generates these files for you.

An origin might give a player the ability to fly, take reduced damage from fire, or apply effects to nearby enemies. All of this is built from combining powers, actions, and conditions.

Origins Mod

How Everything Fits Together

Think of it like building blocks. At the top is a Layer — it's the selection screen players see when they join. Inside the layer are Origins — the actual species players can pick. Each origin has a list of Powers — the abilities that origin has. And powers are built from Actions and Conditions.

📋 Layer

The origin selection screen. Contains a list of origins players can choose from.

⭐ Origin

A playable species like "Angel" or "Merling". Has a name, icon, and a list of powers.

⚡ Power

A single ability. Each power does one thing — fly, glow, deal damage on hit, etc.

▶ Action
◆ Condition

The building blocks that make powers do things and check requirements

Actions are things that happen — they're verbs. Set the player on fire. Deal damage. Teleport. Give an item. A power triggers actions when it activates.

Conditions are checks — they return true or false. Is the player in water? Is it night? Is the entity on fire? Powers use conditions to decide when they should be active. Actions use conditions to decide who they should affect.

📌 Example

An "Angel" origin might have a "Wings" power that gives elytra flight — always on, no conditions needed. It might also have a "Holy Aura" power that sets nearby enemies on fire, but only during the day — that's a power with a time of day condition attached, and a set on fire action as the effect.

Origins Mod

Powers

A power is a single ability assigned to an origin. Each power has a type that defines what it does, plus optional fields to configure it.

⚡ POWER — GENERAL
Passive and always-on abilities. Flight, night vision, attribute modifiers, resource bars.
🎯 POWER — ACTION
Triggered abilities. Active skills with cooldowns, key-bound actions, actions on hit.
✏️ POWER — MODIFY
Modifiers that change game values. Damage dealt, damage taken, jump height, swim speed.
🛡 POWER — PREVENT
Blocks certain actions. Prevent fall damage, prevent eating certain foods, prevent sprinting.

Every power can have an optional condition that determines when the power is active. For example, a fire resistance power could have a condition that only activates it at night.

Origins Mod

Actions

Actions are things that happen — they're verbs. Apply an effect, deal damage, teleport, set on fire, give an item.

Actions come in four types based on what they affect:

🧍 ENTITY ACTION
Affects a single entity — the player, a mob. Apply effect, damage, heal, set on fire.
👥 BI-ENTITY ACTION
Affects a pair of entities — actor and target. Used in area of effect, on-hit actions.
🧱 BLOCK ACTION
Affects a block in the world. Set block, explode, bone meal.
🗡️ ITEM ACTION
Affects an item stack. Damage item, consume, modify NBT.
💡 Tip

Use AND Actions to run multiple actions at once, and If-Else Action to branch based on a condition.

Conditions

Conditions are checks — they return true or false. Is the player in water? Is it night? Is the entity on fire?

They're used in three places: on a power to control when it's active, on an action to filter which entities it affects, and on a bientity action to filter which actor/target pairs it applies to. They come in the same types as actions — plus damage conditions for checking what kind of hit occurred.

🧍 ENTITY CONDITION
Checks something about a single entity. In water, on fire, health below 50%, sneaking, holding item.
👥 BI-ENTITY CONDITION
Checks the relationship between two entities. Actor is owner of target, entities are on the same team.
🧱 BLOCK CONDITION
Checks something about a block in the world. Block is air, is fluid, has a specific tag.
🗡️ ITEM CONDITION
Checks something about an item stack. Is a specific item, has an enchantment, stack count.
💢 DAMAGE CONDITION
Checks the type of damage taken or dealt. Is it fire damage? Fall damage? A projectile?
💡 Tip

Use AND Conditions to require multiple checks at once, OR Conditions to accept any of them, and NOT Condition to invert a check — e.g. "not on fire".

Using the Editor

Editor Basics

The block editor lets you build power JSON visually by dragging and connecting blocks.

1
Pick a block from the palette
Click a category in the left sidebar (Power, Action, Condition, Meta) to open the palette. Drag a block onto the canvas.
2
Fill in the fields
Each block has input fields for its properties. Click any field to edit it. Dropdowns show valid options.
3
Connect child blocks
Drag child blocks from the palette and drop them into the slot areas at the bottom of parent blocks. The connector bump snaps into the notch.
4
Copy or export the JSON
Click ⬇ COPY JSON to copy the generated JSON to clipboard, or save it directly from the Manager.
Using the Editor

Block Types & Colors

Every block has a color that tells you what type it is. You can only place a block into a slot that accepts its type — the editor will highlight valid slots when you drag.

Powers — always the top/root block

⚡ POWER — GENERAL
Passive abilities that are always active — night vision, flight, attribute bonuses.
🎯 POWER — ACTION
Active abilities triggered by a key press or an in-game event.
✏️ POWER — MODIFY
Changes a number — damage dealt, swim speed, jump height.
🛡 POWER — PREVENT
Stops something from happening — fall damage, eating certain food.

Actions & Conditions — share colors by world type

Actions and conditions that affect the same type of thing share the same color. For example, Entity Actions and Entity Conditions are both teal — they both deal with single entities.

🧍 ENTITY
Things involving a single entity (player or mob).
Entity Action + Entity Condition
👥 BI-ENTITY
Things involving two entities at once — an actor and a target.
BiEntity Action + BiEntity Condition
🧱 BLOCK
Things involving world blocks.
Block Action + Block Condition
🗡️ ITEM
Things involving item stacks.
Item Action + Item Condition
💢 DAMAGE
Checks what type of damage was dealt or received.
Damage Condition only
🔗 META
Logic blocks: AND, OR, If-Else, Chance, Invert. Work across all types — place them in any action or condition slot.
Using the Editor

Connecting Blocks

Blocks connect to each other through slots — the dashed drop zones at the bottom of parent blocks. Child blocks snap in using a bump-and-notch system, just like real building blocks.

Visual example

⚡ POWER — GENERAL   Active Self
cooldown  20
key  key.origins.primary_active
ENTITY_ACTION  ↓ drop here
🧍 ENTITY ACTION   Set On Fire
duration  5

The Set On Fire entity action is connected into the entity_action slot of the Active Self power. When the player presses the key, they are set on fire.

How to connect

1
Drag from the palette
Find the block you want in the palette on the left and drag it toward the slot on the parent block.
2
The slot highlights
When you hover over a valid slot, it lights up to show you can drop there. Only slots that accept the block type will highlight.
3
Release to snap in
Let go and the block snaps in. The bump on the parent connects with the notch on the child.

Multi-slots

Some slots accept multiple blocks — like the AND Actions block which runs several actions in sequence. You can keep dropping more blocks into it and they stack up.

Detaching a block

Click and drag any connected block to pull it out of its slot. It becomes a free block on the canvas and you can move it somewhere else or reconnect it to a different slot.

⚠️ Wrong type?

If a slot doesn't light up when you hover over it, the block type doesn't match. Check the slot label — it tells you exactly what type it needs (e.g. entity_action, condition).

Using the Editor

Importing JSON

Already have an Origins JSON file? Paste it directly into the editor and it converts to blocks automatically.

1
Click ⬆ IMPORT JSON in the toolbar
Opens the import modal with a text area.
2
Paste your JSON
You can paste the raw JSON directly — even with // comment lines at the top (like file path comments), these are stripped automatically.
3
Click Import
The parser reads the type fields, creates the correct blocks, fills their values, and connects nested objects as child blocks. An undo snapshot is saved automatically.

Using the Manager

Manager Basics

The Manager is where you organize all your Origins content and export it as a datapack.

Everything is organized under a namespace — your mod's unique identifier. Inside a namespace you create origins, powers, and layers. When you're ready, export everything as a ZIP that drops straight into a Minecraft datapack folder.

Using the Manager

Namespaces

A namespace is your mod's unique ID — like divinity or chaos. It must be lowercase with no spaces.

All your origins and powers will be referenced as namespace:id — for example divinity:stormpiercer.

⚠️ Important

Choose your namespace carefully — changing it later means updating all references. It should be unique to your mod to avoid conflicts with other datapacks.

Using the Manager

Origins & Powers

Under each namespace you create Origins and Powers separately, then link them together.

Creating a Power

Go to the Powers tab and click + New Power. Give it a name and ID, then click Create & Edit — this opens the block editor where you build what the power actually does. When you're done, click 💾 Save Power to save it back to the Manager. A green dot means the power has been saved, yellow means it hasn't been built yet.

Creating an Origin

Go to the Origins tab and click + New Origin. Fill in:

●
Name & Description
What players see in the selection screen.
●
Icon Item
A Minecraft item ID shown as the icon — e.g. minecraft:feather.
●
Impact (0–3)
How powerful this origin is. Shown as stars in the selection screen.
●
Assign Powers
Tick the powers you want this origin to have. Only saved powers appear here.
Using the Manager

Layers

An origin layer controls which origins appear in the selection screen. Without a layer file, your origins won't show up in-game.

The default layer file is named origin.json and goes in data/origins/origin_layers/. Set replace to false to add your origins to the existing selection screen rather than replacing it entirely.

📌 Note

The order field controls the sort position of your layer relative to other mods. Lower numbers appear first.

Using the Manager

Exporting Your Datapack

When you're happy with everything, click ⬇ Export ZIP in the header. This downloads a ZIP file that is a complete, ready-to-use Minecraft datapack.

1
Click ⬇ Export ZIP
Make sure all your powers have a green dot — that means they've been built and saved. Yellow dots mean the power hasn't been edited yet and won't be included.
2
Extract the ZIP
Unzip the downloaded file — you'll see a folder structure with your origins and powers inside.
3
Drop it into Minecraft
Copy the extracted folder into your Minecraft world's datapacks folder — found at .minecraft/saves/<worldname>/datapacks/. Launch Minecraft, load the world, and your origins will appear in the selection screen.
💡 Don't forget the Layer

Make sure you've created a Layer in the Layers tab and added your origins to it — without a layer, your origins won't show up in the selection screen even if everything else is correct.
